## Problem 1 — Why PAM is too slow on big data

(a) 2 × (4 − 2) = 2 × 2 = **4 swap checks per round**.

(b) 2 × (100,000 − 2) = 2 × 99,998 = **199,996 ≈ 200,000 swap checks per round**.

(c) PAM's work per round is k × (n − k), which grows roughly like n² (quadratic). Doubling n roughly quadruples the number of swap checks — and on top of that, every single check reassigns all n points and recomputes the whole cost, so the per-check work doubles too.

(d) The **distance (dissimilarity) matrix**: it has one entry per pair of points, so it grows as n². For n = 100,000 that's ~10 billion entries — far beyond memory.

## Problem 2 — The CLARA recipe, in your own words

(a) **Sample**: a small random subset of the dataset. **Sampsize**: the number of points in each sample (CLARA's default is 40 + 2k). **Full-data cost**: a candidate medoid set's PAM cost computed on every point of the full dataset — the single number used to pick the winner.

(b) 1. Draw several random samples, each of fixed size sampsize. 2. Run PAM on each sample (fast, because each sample is small) — each run returns its own medoid set. 3. For each candidate medoid set, compute the cost on the FULL dataset and keep the set with the lowest cost.

(c) The sample is only a cheap *search* space for finding candidate centers; the full-data cost is the *judge*. Judging on everything guarantees the winner is the candidate that actually fits the whole dataset best, not just the one that got lucky on its own small sample.

## Problem 3 — Sampsize arithmetic

(a) 40 + 2×2 = **44 points per sample**.

(b) 40 + 2×5 = **50 points per sample**.

(c) **30** — sampsize is capped at n, and you can't sample 44 distinct points from 30 rows. (With n = 30, CLARA is pointless anyway — just run PAM on the whole thing.)

(d) PAM's swap phase does k × (n − k) checks per round, so shrinking n from 100,000 to 44 collapses ~200,000 checks per round down to 2 × 42 = 84.

## Problem 5 — Picking the winner + honest caveats

(a) **Sample 2** — its full-data cost (9.88) is the lowest of the three.

(b) Averaging medoids would blend good centers with bad ones and the average of two real points isn't even a data point — breaking the whole medoid promise. Measuring keeps the single best real-point answer.

(c) A 44-point random sample will very likely contain **zero** of the 12 rare points, so CLARA can miss the tiny group entirely. The R docs suggest raising `samples` (the number of samples — e.g. 50 instead of the default 5) so more draws get more chances to catch it.

(d) `pamLike = TRUE` makes the swap phase inside each sample use **PAM's own swap algorithm** (FALSE keeps the older back-compatible variant). The class script sets TRUE so each sample is clustered exactly the way PAM would cluster it.
